6. 最佳实践

6.1 操作前准备

1

在测试环境先验证

在生产环境操作前，务必在测试环境完整验证整个流程。

2

备份重要数据

虽然工具会自动备份，但建议提前手工备份关键数据。

3

检查 Excel 数据正确性

确认唯一标识列准确无误，待更新数据格式正确。

4

确认数据库账号权限

确保账号有 CREATE TABLE、UPDATE、DROP TABLE 等必要权限。

6.2 数据更新建议

建议说明
小批量测试先用几十条数据测试，确认无误后再全量更新
不要关闭程序操作期间保持程序运行，避免中断导致异常
保存更新日志导出日志文件，便于后续审计和问题排查
分批执行大数据量（>1万条）建议分批执行，每批不超过 1 万条
避免高峰期选择数据库负载较低时段执行批量更新

6.3 Excel 数据建议

建议说明
使用提供的模板确保格式正确，避免导入错误
第一列唯一标识不能为空每条记录必须有唯一标识用于匹配
数据类型与数据库一致数字列不要填写文本，日期列使用标准格式
避免特殊字符避免在数据中使用换行符、制表符等特殊字符
使用 .xlsx 格式推荐使用 .xlsx 格式，兼容性更好
空字段保留原值不需要更新的列可以留空，不会被更新为 NULL

6.4 日常维护建议

  • 定期清理历史记录：避免历史记录过多影响性能
  • 定期备份配置：保存 config.json 文件的备份
  • 保存重要的审计日志：将关键操作的日志导出存档
  • 关注日志中的错误和警告：及时发现和解决潜在问题

6.5 安全建议

安全须知：
  1. 在测试环境充分验证后再在生产使用
  2. 更新前自动备份，失败可回滚
  3. 审计日志记录所有操作
  4. 密码使用 Base64 编码存储在本地配置文件
  5. 定期备份重要数据

7. 技术支持

如遇到问题，请按以下顺序排查：

  1. 查看日志文件（logs 目录）
  2. 查看本文档的常见问题章节
  3. 查看操作日志排查原因
  4. 联系技术支持
