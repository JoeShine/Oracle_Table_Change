DBForge (Database Forge) - 功能清单与使用流程
版本: v2.9.0（多数据库支持版）

═══════════════════════════════════════════════════════════════

一、功能清单

═══════════════════════════════════════════════════════════════

[✓] 连接管理管理
    ├─ 支持配置多个连接管理（Oracle / MySQL / SQL Server）
    ├─ 保存连接信息到本地配置文件
    ├─ 测试连接功能
    ├─ 删除连接配置
    └─ 自动保存最近使用的连接

[✓] 多数据库支持（v2.9.0 核心特性）
    ├─ Oracle       11g / 12c / 19c / 21c       - 驱动: oracledb
    ├─ MySQL        5.7+ / 8.0+ / MariaDB 10.x   - 驱动: pymysql
    ├─ MS SQL Server 2008 R2 / 2012+ / 2016 / 2019 / 2022  - 驱动: pyodbc + MS ODBC Driver 17
    ├─ 自动 SQL 方言适配（DDL / DML 语法随数据库类型自动切换）
    ├─ 统一的 DB-API 2.0 抽象层
    └─ 连接管理页支持数据库类型选择

[✓] Excel 数据处理
    ├─ 支持导入 .xlsx 和 .xls 格式
    ├─ 验证 Excel 结构（至少 2 列）
    ├─ 检查唯一标识列重复
    ├─ 预览 Excel 数据（前 10 行）
    ├─ 导出日志到 Excel
    └─ 导出失败记录到 Excel

[✓] 数据备份
    ├─ 自动备份目标表到对应 Schema/Database
    ├─ 备份表命名：原表名_BAK_YYYYMMDD_HHMMSS
    ├─ 备份完整表结构和数据
    └─ 备份后可恢复

[✓] 数据更新
    ├─ 创建临时表存储 Excel 数据
    ├─ 临时表命名：TEMP_UPDATE_YYYYMMDD_HHMMSS
    ├─ 自动清理临时表
    ├─ 批量插入 Excel 数据
    ├─ 方言自适应 MERGE / ON DUPLICATE KEY UPDATE / 其他
    ├─ 逐行更新并验证
    └─ 记录成功和失败数量

[✓] 日志管理
    ├─ 实时显示运行日志
    ├─ 支持 INFO / 成功 / 错误 / 警告 级别
    ├─ 日志写入文件
    ├─ 导出完整日志到 Excel
    └─ 记录失败记录详情

[✓] 配置保存
    ├─ 保存最近使用的配置
    ├─ 自动恢复上次输入
    ├─ 配置文件加密（可选）
    └─ 支持多用户配置

[✓] 用户界面
    ├─ 图形化操作界面
    ├─ 连接管理配置面板（含数据库类型选择）
    ├─ 更新参数配置面板
    ├─ Excel 数据预览
    ├─ 实时日志显示
    ├─ 失败记录弹窗提醒
    ├─ 导出按钮
    └─ 三套主题风格切换（默认深墨琥珀 terminal + Idea 蓝色 + 清爽浅色）+ 深浅色模式 + 持久化 theme_style/theme_dark + set_dark_mode 启动恢复

三、详细操作步骤

═══════════════════════════════════════════════════════════════

步骤 1：配置连接管理
───────────────────────────────────────────────────────────────
1. 点击 "添加连接" 按钮
2. 选择数据库类型：Oracle / MySQL / SQL Server
3. 填写连接信息：
   - 连接名称：给连接起个名字，如 "生产库"
   - 主机地址：数据库服务器 IP 地址
   - 端口：Oracle 默认 1521 / MySQL 默认 3306 / SQL Server 默认 1433
   - 服务名/数据库名：Oracle 用 service_name，MySQL/SQL Server 用 database 名称
   - 用户名：数据库用户名
   - 密码：数据库密码
   - （SQL Server 可选）ODBC DSN 或直接使用 Driver={ODBC Driver 17 for SQL Server}
4. 点击 "测试连接" 验证
5. 连接成功后点击 "确定" 保存

步骤 2：准备 Excel 文件
───────────────────────────────────────────────────────────────
Excel 文件格式要求：
┌────────────┬──────────────────────────┐
│   USER_ID  │          EMAIL            │  ← 表头
├────────────┼──────────────────────────┤
│   1001     │ zhangsan@example.com      │  ← 数据行
│   1002     │ lisi@example.com          │
│   1003     │ wangwu@example.com        │
└────────────┴──────────────────────────┘

说明：
- 第一列：唯一标识列（必须）
- 第二列：待修改数据列（必须）
- 可以有更多列，但只使用前两列
- 不能有重复的唯一标识值

步骤 3：配置更新参数
───────────────────────────────────────────────────────────────
1. 从下拉框选择已保存的连接管理
2. 输入目标表名（如：USER_INFO）
3. 输入唯一标识列名（如：USER_ID）
4. 输入待修改列名（如：EMAIL）
5. 点击 "浏览" 选择 Excel 文件
6. 点击 "预览" 查看 Excel 数据

步骤 4：执行更新
───────────────────────────────────────────────────────────────
1. 点击 "开始更新" 按钮
2. 系统自动执行（SQL 方言随数据库类型自动切换）：
   - 连接数据库
   - 备份目标表
   - 创建临时表
   - 导入 Excel 数据
   - 执行更新
   - 清理临时表
3. 查看日志了解进度
4. 如有失败记录会弹窗显示

步骤 5：查看和导出结果
───────────────────────────────────────────────────────────────
1. 在日志区域查看完整操作记录
2. 点击 "导出日志" 保存完整日志
3. 点击 "导出失败记录" 保存失败详情

五、错误处理

═══════════════════════════════════════════════════════════════

常见错误及解决方案：

1. 连接失败 - Oracle TNS: 无监听程序 / MySQL Access denied / SQL Server 登录失败
   → 检查主机地址和端口是否正确；检查用户权限

2. 连接失败 - 用户名/密码无效
   → 检查用户名和密码

3. 连接失败 - 无法解析服务名/数据库名
   → 检查 service_name 或 database name 是否正确

4. 表不存在
   → 确认目标表名拼写正确，注意大小写（Oracle 默认大写，MySQL/Linux 默认区分）

5. 列不存在
   → 确认列名拼写正确，注意大小写

6. 数据类型不匹配
   → 检查 Excel 数据类型是否与目标列兼容

7. 唯一标识重复
   → Excel 中的唯一标识列不能有重复值

8. 记录不存在
   → Excel 中的 ID 在目标表中不存在

9. SQL Server 专用：找不到 Microsoft ODBC Driver 17 for SQL Server
   → 从微软官网下载并安装 ODBC Driver 17 for SQL Server

10. MySQL 专用：caching_sha2_password 认证失败
    → 升级 pymysql 到 0.9.3+ 或在 MySQL 端改用 mysql_native_password

六、备份与恢复

═══════════════════════════════════════════════════════════════

备份位置：对应 Schema / Database 下
备份表名：原表名_BAK_YYYYMMDD_HHMMSS

恢复方法（如需要）：

Oracle:
SELECT * FROM "原表名_BAK_YYYYMMDD_HHMMSS";
CREATE TABLE "原表名" AS SELECT * FROM "原表名_BAK_YYYYMMDD_HHMMSS";

MySQL:
SELECT * FROM `原表名_BAK_YYYYMMDD_HHMMSS`;
CREATE TABLE `原表名` AS SELECT * FROM `原表名_BAK_YYYYMMDD_HHMMSS`;

SQL Server:
SELECT * FROM [原表名_BAK_YYYYMMDD_HHMMSS];
SELECT * INTO [原表名] FROM [原表名_BAK_YYYYMMDD_HHMMSS];

七、技术支持

═══════════════════════════════════════════════════════════════

如遇问题，请检查：
1. logs/ 目录下的日志文件
2. config.json 配置文件
3. 数据库驱动是否正确配置（oracledb / pymysql / pyodbc + MS ODBC Driver 17）
4. 数据库权限是否足够

联系信息：
- 查看日志获取详细错误信息
- 导出日志便于分析问题
